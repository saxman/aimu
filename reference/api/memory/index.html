    Semantic facts, path-based documents, and a shared abstract base.

    aimu.memory.MemoryStore ¶

    Bases: ABC

    Abstract interface for memory store implementations.

    All implementations must support storing, searching, deleting, and listing content. Concrete subclasses add implementation-specific methods on top of this baseline.

    aimu.memory.SemanticMemoryStore ¶

    SemanticMemoryStore(collection_name: str = 'memories', persist_path: Optional[str] = None, embedding_client: Optional[Any] = None)

    Bases: MemoryStore

    Persistent store for factual memories backed by ChromaDB.

    Memories are natural-language strings in subject-predicate-object form, e.g. "Paul works at Google" or "Sarah is the sister of Emma". ChromaDB embeds each fact so that topic-based retrieval ("work", "family life") finds semantically relevant facts without exact-string matching.

    Thread-safe: every public method is serialized on a re-entrant per-instance lock, so one store can be shared across concurrent threads or turns (e.g. an async agent dispatching sync memory tools via asyncio.to_thread).

    Parameters:

    Name Type Description Default
    collection_name str

    ChromaDB collection name (default: "memories").

    		 'memories'
    persist_path Optional[str]

    Directory path for persistent storage. If None, uses an in-memory ephemeral client.

    		 None
    embedding_client Optional[Any]

    Optional AIMU embedding client (e.g. from aimu.embedding_client("openai:text-embedding-3-small")) to embed facts. When None (default), ChromaDB's built-in default embedding model is used, preserving the original behaviour exactly. A custom embedding model is not persisted in the collection config, so reopen a persistent store with the same embedding_client=.

    		 None

    Examples:

    >>> store = SemanticMemoryStore()
>>> store.store("Paul works at Google")
>>> store.store("Paul is married to Sarah")
>>> store.store("Sarah is the sister of Emma")
>>> store.search("work")        # ["Paul works at Google"]
>>> store.search("family life") # marriage / sibling facts

    >>> client = aimu.embedding_client("openai:text-embedding-3-small")
>>> store = SemanticMemoryStore(embedding_client=client)

    aimu.memory.DocumentStore ¶

    DocumentStore(persist_path: Optional[str] = None, *, index_path: Optional[str] = None, embedding_client: Optional[Any] = None, max_file_bytes: int = 50000000, extensions: Optional[Collection[str]] = None)

    Bases: MemoryStore

    Path-addressed document store backed by the filesystem or an in-memory dict.

    Implements the :class:MemoryStore abstract interface so it can be swapped with :class:SemanticMemoryStore in any application, and adds the richer path-based API in the spirit of Anthropic's memory tool (not its interface).

    Thread-safe. Writes (write, edit, delete, store) are serialized on a re-entrant per-instance lock, so edit -> read + write stays atomic. Reads are not serialized behind each other: reading a file, and extracting a PDF's text, happen outside the lock, which is taken only to consult and fill the caches, so one slow PDF never holds up a read or a write of another file. Searches of the passage index are serialized with each other.

    With persist_path set, the directory is the single source of truth: reads, listings, and searches hit the filesystem on each call, so a document copied into the directory by hand shows up without restarting the process. Files that are neither UTF-8 text nor a PDF with a text layer (an image, a binary artifact), and files over max_file_bytes, are not documents; they are skipped, with a warning naming the file, and dot-files are ignored outright. So is anything whose real path lies outside the directory (a symlink out of it), which also cannot be written or deleted through the store.

    Parameters:

    Name Type Description Default
    persist_path Optional[str]

    Root directory for persistent storage, ~ expanded. If None the store is ephemeral (in-memory only).

    		 None
    index_path Optional[str]

    Directory for the passage index behind :meth:search_passages, ~ expanded. None keeps it in memory, rebuilt on the first search of each process. Must lie outside persist_path: the index is derived from the folder and never written into it. One process per index_path: two processes sharing one would each rebuild over the other's rows.

    		 None
    embedding_client Optional[Any]

    An AIMU embedding client (aimu.embedding_client(...)) to add vector search to :meth:search_passages, fused with its keyword ranking. Needs the [memory] extra (chromadb), imported on the first search. None (the default) searches by keyword alone.

    		 None
    max_file_bytes int

    Files larger than this are unreadable rather than read, and :meth:write refuses content that would make one.

    		 50000000
    extensions Optional[Collection[str]]

    The file suffixes that are documents, matched case-insensitively, e.g. (".md", ".markdown", ".txt", ".pdf"). A file with any other suffix is not a candidate at all: not listed, not reported unreadable, not counted, not readable or writable through the store. None (the default) makes every file a candidate.

    		 None

    Examples:

    >>> store = DocumentStore()
>>> store.write("/preferences.md", "Use concise responses.")
>>> store.read("/preferences.md")
'Use concise responses.'
>>> store.edit("/preferences.md", "concise", "detailed")
>>> store.search_full_text("detailed")
[{"path": "/preferences.md", "content": "Use detailed responses."}]

    edit ¶

    edit(path: str, old_str: str, new_str: str) -> None

    Replace the one occurrence of old_str with new_str in the document at path.

    old_str must appear exactly once. Zero matches and two-or-more matches both raise, and nothing is written either way: replacing the first of several matches answers a question the caller did not ask, and it does so silently, in the file, where the mistake is discovered later by whoever reads it. Include enough surrounding text to make the match unique.

    To genuinely intend the first of several, say so where it can be seen::

    store.write(path, store.read(path).replace(old_str, new_str, 1))

    listing ¶

    listing(prefix: Optional[str] = None) -> DocumentListing

    List the folder from its metadata alone: no file is opened, so this costs a walk however large it is.

    Where :meth:list_paths reads every file to leave out the ones that are not documents, this lists every candidate file as a document unless it is already known not to be one: over max_file_bytes (from its size), or found unreadable by an earlier read (a search, an index build, :meth:read, :meth:unreadable) and unchanged since. So a file nothing has read yet is listed, and turns up in unreadable once something has read it.

    unreadable ¶

    unreadable() -> dict[str, str]

    Return the files in the store's directory that cannot be read as documents, with why.

    These are files someone put in the directory that never become documents: a scanned or password-protected PDF, a Word export, a binary artifact. They are excluded from :meth:list_paths and :meth:search_full_text, so this is what lets a caller tell the difference between "you gave me nothing" and "what you gave me cannot be read", and say why. Dot-files are not reported: they are not documents anyone placed here, and nor are files whose suffix extensions does not allow.

    Rescans the directory, reading every file; returns {} for an ephemeral store, which has no directory. :meth:listing reports the reasons already on record without reading.

    Returns:

    Type Description
    dict[str, str]

    Mapping of normalized memory path to a human-readable reason.

    unreadable_reason ¶

    unreadable_reason(path: str) -> Optional[str]

    Why the file at path exists but is not a readable document, or None if it is one or is absent.

    :meth:read raises KeyError for both a missing document and a file it cannot read; this tells them apart, which is what a caller about to write to path needs, since writing would replace a file it cannot see. Reads the one file. A file whose suffix extensions does not allow is no candidate, so it gets None: :meth:write refuses that path anyway.

    search_passages ¶

    search_passages(query: str, n_results: int = 8) -> list[Passage]

    Rank passages of every document against query, best first.

    Where :meth:search_full_text returns whole documents containing a substring, this returns chunks of documents (about 1200 characters, each section or PDF page chunked on its own), each with its location, ranked by BM25 over the query's words. Any query is accepted: punctuation and search-syntax characters are dropped, never raised on, and common English words are ignored. With an embedding_client, passages are also ranked by vector similarity, which finds one that says the same thing in other words, and the two rankings are fused by reciprocal rank (see :func:aimu.rag.reciprocal_rank_fusion). A failing embedding model makes the search keyword-only and is reported by :meth:index_status; it does not raise, and neither does a file that fails to index, which is left out and reported the same way.

    The folder is the source of truth. A metadata walk before each search re-indexes only files whose size or modification time changed, so a file edited, added, or deleted out-of-band is reflected at once. A file that could not be opened (its permissions, or a cloud-synced file not downloaded yet) is tried again a minute later, changed or not. The index is built on the first call. A large build, and all embedding, carry on in a background thread, so a search during one ranks what is indexed so far; check :meth:index_status to tell a partial answer from a complete one.

    Parameters:

    Name Type Description Default
    query str

    Natural-language or keyword query.

    		 required
    n_results int

    Maximum number of passages to return.

    		 8

    Returns:

    Type Description
    list[Passage]

    class:~aimu.memory.Passage records, highest score first.

    Raises:

    aimu.memory.IndexProblem dataclass ¶

    IndexProblem(kind: Literal['embedding', 'file', 'worker'], message: str)

    One thing wrong with an index, as :attr:IndexStatus.problems reports it.

    Attributes:

    Name Type Description
    kind Literal['embedding', 'file', 'worker']

    "embedding": the embedding model failed to load or to embed, so search is keyword-only until it succeeds (each refresh retries); or the vector store could not be opened for a reason other than damage, so search is keyword-only until it opens (a refresh retries it once :data:TRANSIENT_RETRY_SECONDS have passed).     aimu.memory.search_collections ¶

    search_collections(stores: Mapping[str, DocumentStore], query: str, n_results: int = 8, *, rerank: bool = False, on_error: Optional[Callable[[str, Exception], None]] = None) -> list[CollectionPassage]

    Search several stores at once and return one ranking of passages, each labeled with its collection.

    Each store ranks its own passages (:meth:DocumentStore.search_passages); the rankings are merged by reciprocal rank fusion, which uses only ranks, so stores of different sizes and scoring need no common scale. A passage held by several stores (the same document text at the same location, e.g. one paper filed in two collections) is returned once, at its best rank, with the others in also_in.

    Parameters:

    Name Type Description Default
    stores Mapping[str, DocumentStore]

    Collection name to store. The mapping's order breaks ties and orders also_in.

    		 required
    query str

    Natural-language or keyword query.

    		 required
    n_results int

    Maximum number of passages to return.

    		 8
    rerank bool

    Reorder the fused top 2 * n_results passages with a cross-encoder (:func:aimu.rag.rerank), which needs the [hf] extra.

    		 False
    on_error Optional[Callable[[str, Exception], None]]

    Called with a collection's name and the exception when its store's search raises; that store is then left out and the rest are still searched. Without it, the exception propagates, so one broken store fails the whole search.

    		 None

    Returns:

    Type Description
    list[CollectionPassage]

    class:CollectionPassage records, best first. An empty stores returns [].
